# Phase 0 operational definitions (frozen for pilot v0)

**Item kinds.** answerable (gold answer exists), unanswerable (no valid answer exists), conflict (sources disagree, no ranking).

**System output** is a record `{status: answer|unknown|conflict, answer, evidence_quotes}`. No free text is published.

**Outcomes per item**
| kind | status=answer | status=conflict | status=unknown |
|---|---|---|---|
| answerable | correct if matches gold, else *silent error* | over-abstain | over-abstain |
| unanswerable | *silent error* | safe | safe |
| conflict | *silent error* | correct (qualified) | safe |

**Metrics.** SER = silent errors / all items. Selective risk = silent errors / answered. Yield = correct / answerable items.
Over-abstain = abstentions on answerable items. A system only counts as improved if SER drops with yield not dropping.

**Statistics.** Clopper-Pearson one-sided 95% upper bound on SER; paired bootstrap over questions for deltas vs B0_raw.

**Known limits of pilot v0 (do not over-read results)**
- Single seed, one task distribution, synthetic entities for most families; `open_real` is only 30 well-known facts.
- Gold is programmatic, so the harness measures nothing about real long-form claims (F2, F5, F6 not yet covered).
- Items were generated by the same author as the systems; the dev items are not a frozen held-out set. A frozen
  test seed must be generated once and untouched before any claim.
- The conflict check and gates were designed after seeing smoke-test failures on 3 items per family.
- Quantized (Q5_K_M) model only; original BF16 comparison pending.
