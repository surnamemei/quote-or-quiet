# VKG Research Programme

Verifiable Knowledge Generation — 从幻觉抑制到可靠知识生成

研究计划 V1.0 · 2026 年 11 月 4 日

这次我把我们此前讨论的目标、理论依据、技术路线、实验方法、统计验证和最终成功标准整合起来。它不是某一篇论文的实验计划，而是一个可以持续推进的研究项目。

整个研究只围绕一个最终目标：解决大语言模型的幻觉问题。

不是专门优化 Qwen，不是只针对 NVFP4，也不是为了发表论文而挑选一个容易得出正面结果的问题。

我们允许研究过程中发现已有技术、推翻假设、替换方法，甚至需要修改模型架构。只要最终使语言模型及其应用系统真正更加可靠，研究就具有价值。

## 一、最终目标是什么？

我建议同时追求两个目标，而不是把它们混为一谈。

Goal A — 消除最终输出中的静默幻觉

让系统不再把未经充分确认的错误事实，以确定性知识的形式交给用户。

当证据不足时，系统应尽可能进一步求证；求证失败则明确表达未知、争议或条件限制。

Goal B — 从模型内部消除幻觉的生成机制

研究模型为什么会把缺失的知识、错误的记忆或不可靠的推断变成确定答案，并尝试从训练、表示、路由或生成机制上解决问题。

最终希望降低对外部验证器的依赖。

Goal A 是相对容易定义严格边界的工程与系统目标；Goal B 是更加基础、更加激进的模型研究目标。

两者并不互相替代。一个外部验证系统可以避免部分错误发布，却不能证明模型本身不再产生幻觉。

### 最终成功状态

理想情况下，对用户的问题 \\(x\\)，系统应该只输出以下三种有意义的结果：

\\[ F(x)\in \begin{cases} \text{Verified Answer}\\\ \text{Qualified / Conditional Answer}\\\ \text{Unresolved + Recovery Plan} \end{cases} \\]

具体含义分别是：

- Verified：在明确的来源、规则和适用范围内，已通过相应验证。
- Qualified：证据有条件、有争议或不完整，结论明确标注其限制。
- Unresolved：现有证据不足，说明缺什么信息，以及是否还能获取。

目标是避免第四种状态：实际上没有可靠依据，却输出看似确定的事实。

但这里有一个严格的科学边界：有证据支持不等于绝对真实。真实世界可能存在错误来源、未知事实或互相冲突的权威记录。

因此，我们可以追求某些形式化任务上的严格保证，以及开放世界任务中极低的漏错风险；不能未经证明就宣称解决了所有可能的事实错误。

## 二、为什么我认为应该这样研究？

我们的理论依据主要来自四个方面。

### 1. 幻觉不是简单的模型容量问题

2026 年 4 月发表于 Nature 的 [Evaluating Large Language Models for Accuracy Incentivizes Hallucinations](https://www.nature.com/articles/s41586-026-10549-w?utm_source=chatgpt.com) 从学习理论和评测激励出发，解释了为什么有限训练数据、下一 Token 预测和奖励猜测的评测会使幻觉持续存在。

[image](https://www.google.com/s2/favicons?domain=https://www.nature.com\&sz=32)

Nature



这意味着更大模型、更高精度和更多训练数据可能改善问题，却不能单独作为彻底消除幻觉的理论依据。

所以我们不能把项目目标简化成“找一个幻觉更少的模型”。

### 2. 正确答案和可信答案不是一回事

模型可能凭猜测得到正确答案，也可能引用真实存在的论文却错误描述其中结论。

因此必须分别研究：

\\[ \text{Factual Correctness} \\]

与

\\[ \text{Evidence Support} \\]

此外，还需要评价证据是否足够、是否过时、是否被错误使用。

FActScore 和 VeriScore 等研究已经证明，长文本中的事实质量需要在原子声明层面分析，而不是简单给整篇回答一个正确或错误的标签。

### 3. 验证器也可能成为错误来源

如果让一个模型生成，另一个模型判断真假，只是引入了第二个不完全可靠的系统。

我们真正需要的是：

在能够形式化的领域使用独立验证；在无法形式化的领域明确记录证据、适用前提和残余不确定性。

因此，项目不能以“多个 LLM 一致认为正确”为最终真值标准。

## 三、研究框架：先识别错误，再决定如何解决

这里需要特别强调：我们不会预先假设所有幻觉都来自同一种机制。

模型规模、训练方式、推理架构和量化方式可能分别影响错误，但仅凭模型的最终输出，通常无法确定内部原因。

因此首先采用两个独立的分类维度。

### A. 可以直接观察的错误

| 类型       | 具体表现              | 如何判断      |
| -------- | ----------------- | --------- |
| F1：事实错误  | 人物、日期、论文结论等错误     | 独立真值核验    |
| F2：无证据断言 | 事实可能正确，但给出的依据不足   | 证据支持检查    |
| F3：上下文冲突 | 已提供正确资料，模型仍输出矛盾内容 | 封闭证据比较    |
| F4：推导错误  | 计算、逻辑、因果链错误       | 独立执行或证明   |
| F5：伪造证据  | 不存在的论文、引用、数据      | 来源真实性审计   |
| F6：过时知识  | 旧事实被当作当前事实        | 时间有效性核验   |
| F7：隐藏失败  | 模型无法求解却继续给出确定结论   | 可回答性和拒答审计 |

这里 F2 与 F1 必须严格区分：证据不足不能直接判定事实为假。

### B. 需要因果实验检验的机制假设

例如，模型可能根本没有相关知识，也可能已有知识却提取失败；可能是长上下文状态保持失败，也可能是 MoE 路由、量化扰动或推理步骤导致错误。

这些只是候选机制。

如果要声称某个 MoE Router 导致幻觉，就必须通过路由反事实实验、模块替换或其他受控干预来证明，不能因为 MoE 的错误率较高就归因于路由。

这也是我们不会一开始就对 Dense、A3B 和大型 MoE 的幻觉率求平均值的原因。

## 四、总体技术路线

我建议以一个可扩展的系统为研究载体，但不把任何组件预先确定为最终答案。

Generation Engine

Evidence & Verification Engine

独立证据核对

通过

允许发布

Constrained Final Output

从允许发布的声明生成回答，禁止加入未获授权的新事实

这一架构需要解决四个真正困难的问题。

第一，事实分解必须完整。 假如回答包含十个声明，检测器只提取出八个，即使这八个全部验证通过，另外两个也可能造成错误。需要对遗漏的事实声明进行独立审计。

第二，验证必须独立。 能计算的交给求解器，能证明的交给证明检查器；其他内容使用可追溯证据。检索文本只能作为数据，不能作为改变系统验证规则的指令。

第三，恢复不能无条件循环。 每次检索或再推理都需要带来新的证据，或者减少关键的不确定性。超过预设预算就停止，不能让系统无限自我检查。

第四，最终表达不能重新引入幻觉。 即使中间的事实表完全正确，语言模型仍可能在润色时补充未经验证的内容。对于严格任务，可以采用受约束的结构化输出或模板渲染，再审计最终文本。

这四个问题中任何一个失败，都足以造成系统级幻觉。

## 五、核心研究命题与定量目标

我建议将项目的总体目标函数定义为：

\\[ \min\_{\pi}\\;P(\text{Silent False Claim}\mid\pi) \\]

其中 \\(\pi\\) 表示系统采取的生成、检查、恢复和输出策略。

同时满足：

\\[ \begin{aligned} \text{Coverage}(\pi)&\ge C\_{\min}\\\ \text{CorrectYield}(\pi)&\ge Y\_{\min}\\\ \text{Cost}(\pi)&\le B\_{\max} \end{aligned} \\]

也就是说：减少静默错误不能靠停止回答，也不能无限消耗计算资源。

### 主要评价指标

| 指标                         | 定义                              | 重要性         |
| -------------------------- | ------------------------------- | ----------- |
| Silent Error Rate（SER）     | 全部问题中，最终发布至少一个未明确限定的错误事实的比例     | 核心安全指标      |
| Unsupported Assertion Rate | 已发布事实声明中，缺乏规定证据支持的比例            | 证据可靠性       |
| Selective Risk             | 已有效回答问题中的错误率                    | 排除拒答带来的虚假改善 |
| Correct Answer Yield       | 全部问题中，正确完成任务的比例                 | 实际能力        |
| Recovery Rate              | 原始失败且客观上可恢复的实例中，最终恢复正确的比例       | 是否解决知识缺口    |
| Evidence Integrity         | 引用是否存在、支持是否充分、时效是否合适            | 防止伪造与误引     |
| Verification Cost          | 每次正确完成任务的额外 Token、时间、检索与 GPU 成本 | 部署价值        |

所有指标都要报告问题级与原子声明级结果，且必须分别统计可回答、不可回答和信息冲突的问题。

### 三个最重要的可证伪假设

H1 — 错误能够在输出前被有效阻断

在相同回答覆盖率和资源预算下，VKG 相比强基线具有更低的静默错误率。

H2 — 错误能够被主动恢复，而非仅仅隐藏

对原本回答错误、但存在可取得证据的问题，VKG 能提高正确答案产出率，并且不显著损害原本正确的答案。

H3 — 可靠性机制具有一定跨架构可迁移性

系统级规则可以跨模型适用；对模型内部机制的结论，则需要在 Dense、MoE、Hybrid 中分别验证。

这三个假设都可能失败。如果失败，我们需要定位原因，而不是改变评价方法让结果显得成功。

## 六、怎么样才算真正解决了幻觉？

我建议设立三个不同层级的成功判据。

## L1

实证改进

在严格对照下明显降低错误

初始工程目标可以设为：同等有效回答覆盖率和计算预算下，SER 相对强基线下降至少 50%，且正确答案产出率不下降。

这是建议的阶段目标，不是现有实验结果。

## L2

统计可靠性

在明确任务分布中将漏错风险控制到足够低

例如把 95% 单侧置信上界压到 1% 以下，并保持预先规定的任务完成率。

需要充分的独立测试样本，不能因为某个小测试集出现零错误就认定已消除幻觉。

## L3

严格保证

在形式化范围内阻止未经验证的声明输出

当输入前提可信、验证器正确、语义映射可靠且输出受严格约束时，证明所有获准发布的事实声明均满足指定验证条件。

这种保证针对形式化约束，并不自动保证开放世界中的事实绝对正确。

最终理想是 L3 范围不断扩大，L2 风险不断降低，同时不牺牲实际能力。

这比简单追求所有测试集上 0% Hallucination Rate 更严谨，也更能体现真正的系统进步。

## 七、完整研究阶段

我会把工作划分成六个阶段，按依赖关系推进，而不是提前把所有模块开发完。

1. Phase 0 — Problem Definition & Measurement Validation

   先建立事实声明标注规范、独立真值体系和测试 Harness。

   覆盖形式化计算、封闭证据、开放世界事实、多轮对话及不可回答问题。检测系统必须先通过人工审计、标签一致性和错误注入测试。

   完成条件： 证明评价体系能够发现生成器、检索器和验证器各自的错误，而不是只有一个无法解释的总分。
2. Phase 1 — Failure Landscape & Theoretical Boundaries

   在不同模型及任务上建立失败画像。

   采用同模型不同精度、同模型不同上下文、同任务不同架构等受控比较。再利用反事实干预区分知识缺失、证据提取失败和模型内部计算错误。

   完成条件： 找到可以重复验证的主要错误模式，并确定哪些错误可以严格验证、哪些只能统计控制。
3. Phase 2 — Minimum Viable Verification System

   建立最小可验证输出协议，优先使用可靠的确定性工具和封闭证据，而不是复杂的多 Agent 系统。

   重点解决事实遗漏、证据错误、错误放行和最终重新编造。

   完成条件： 在受控任务中，相较于原模型、简单拒答、RAG 等基线，显著减少静默错误，同时保持有效输出。
4. Phase 3 — Active Uncertainty Recovery

   将未解决的事实转化为具体的求证任务。

   研究什么情况下值得检索、执行计算、调用其他模型或向用户请求额外信息，并对恢复成本设定限制。

   完成条件： 独立证明正确答案产出率上升，而不只是拒答率增加。
5. Phase 4 — Model-Internal Mechanism & Intervention

   如果外部验证的成本、误报率或可恢复性形成瓶颈，就研究模型内部干预。

   候选方向包括隐藏状态中的事实可靠性信号、MoE 路由机制、长上下文状态更新、训练目标与不确定性校准。

   完成条件： 新干预具有可重复的因果效果，并且相比纯外部系统能减少成本或改善可靠性。
6. Phase 5 — Generalization, Assurance & Deployment

   冻结方法，在未用于开发的模型和任务上测试。完成跨架构、上下文长度、量化精度、证据冲突以及对抗性输入的外部验证。

   完成条件： 明确哪些保证成立、哪些条件下会失败，以及系统是否适合实际本地部署。

这不是必须从 0 顺序执行到 5 的瀑布式开发。Phase 1 发现新机制，可以反馈 Phase 2；Phase 3 发现无法恢复的系统性缺陷，也可以提前触发 Phase 4。

## 八、实验应该怎么设计，才能得到可信结论？

### 1. 不要一开始就做全模型大网格

我们先选择覆盖不同机制的模型，而不是随意挑选四个流行模型。

| 实验层                | 研究对象        | 目的             |
| ------------------ | ----------- | -------------- |
| 小规模 Dense          | 可运行高精度参考的模型 | 研究基础幻觉、量化、内部激活 |
| 小激活量 MoE           | A3B 一类      | 测试专家路由及跨架构适用性  |
| 中大型 Dense / Hybrid | 约 27B 级     | 验证规模与上下文机制变化   |
| 大型 MoE / Hybrid    | 更大总参数量模型    | 外部泛化与实用性能测试    |

具体版本在实验冻结时确定。不能因为某个模型标有 A3B，就把它当成 3B Dense，也不能把稀疏注意力与专家稀疏激活看作同一个变量。

你的 RTX 5090 可承担早期大量实验；无法在本地完成的 BF16 大模型对照，再考虑多卡或短期云端资源，而不是强行 CPU Offload 后比较未经控制的速度。

### 2. 对照组与消融

| 对照                          | 要排除的解释      |
| --------------------------- | ----------- |
| 原始模型                        | 自然错误基线      |
| Prompt + 拒答校准               | 是否只是更谨慎     |
| 标准 RAG                      | 是否只是拿到了更多知识 |
| 验证但不恢复                      | 单独测量拦截的价值   |
| 验证 + 恢复                     | 测量主动求证的增益   |
| Oracle 证据 / Oracle Verifier | 确定瓶颈来自哪里    |
| 完整系统                        | 最终端到端表现     |

在独立测试问题上使用配对实验，并同时报告同等覆盖率与同等计算预算的结果。

由于一条问题可能产生多个事实，统计置信区间应按照原始问题进行聚类，而不是把所有 Claim 当成独立观测。

### 3. 数据规模与统计要求

初步 Pilot 可以采用约 200–300 个独立问题，用来检查数据标注和系统可行性。

正式测试的样本量应根据 Pilot 得到的配对效应量、基线错误率和目标置信区间计算；每个主要测试条件可能需要数百至上千个独立实例。

对于非常低的目标错误率，样本需求更大。例如零错误的 1,000 个独立试验，对总体错误率的 95% 单侧上界仍约为 0.3%。

另外，测试必须包括独立人工审计和完全冻结的验证集，不能让自动 LLM 评判器同时负责开发调参和最终裁决。

## 九、怎么避免整个研究做着做着变成 RAG 工程？

这是我认为最需要提前建立的判断规则。

每个阶段都应能回答一个独立的科学问题。

| 可能出现的结果           | 应该怎么处理                   |
| ----------------- | ------------------------ |
| 普通 RAG 已实现相同收益    | 不把复杂 VKG 作为新算法，分析其他未解决错误 |
| 错误率下降但正确产出也下降     | 修改策略，不能宣布成功              |
| 错误恢复成功，但只是调用更强的模型 | 做等预算对照，分清贡献来源            |
| 验证器漏错成为主要瓶颈       | 研究验证可靠性，必要时更换验证机制        |
| Dense 有效而 MoE 无效  | 限定结论，寻找架构特有原因            |
| 发现已有论文提出相同方法      | 复现并建立基线，继续寻找剩余问题         |
| 严格保证无法扩展到开放世界     | 明确保证边界，研究更合理的统计风险控制      |

2026 年 10 月发表的 FreeGuard 已经研究了声明级图推理、双向证据和反事实证据检查。因此，这些现成组件不能因为被我们重新组合，就自动成为理论创新。

## 十一、我认为最合理的启动方式

现在不需要马上修改 Qwen 模型权重，也不需要立刻写一个庞大的 Agent 框架。

第一个实际研究任务应当是：

构建一个能够被独立审计的事实输出实验环境，并证明我们能正确测量“静默错误 → 识别 → 恢复 → 最终输出”的全过程。

第一轮应当冻结三样东西：事实与错误的操作性定义、基线与评价标准、严格独立的真值来源。

随后做最小实验，回答一个很尖锐的问题：

> 对于原模型本来会发布的错误事实，我们能否将它们转变为正确答案或明确的未知状态，并且不损失原本正确的回答？

如果这个实验成立，就可以继续追求更严格的保证。如果不成立，先确定是事实提取、验证器还是恢复策略的失败，再决定是否需要直接干预模型内部。

## 最终结论

整个计划的核心研究主线

我们真正追求的是：

让幻觉从无法察觉的错误，变成可检测、可解释、可恢复，并最终在明确范围内可被严格排除的系统状态。

对于开放世界问题，追求接近零的未检出错误风险；对于能够形式化的任务，追求在可信前提下严格禁止未经验证的事实输出；对于模型本身，则继续研究如何从内部减少错误生成。

这样，无论未来模型是 Dense、MoE、Hybrid，还是采用完全不同的架构，我们的研究问题都仍然成立。

我会把这个版本作为 VKG 的研究基线：长期目标不降低，方法不预设，阶段结论必须有证据；创新性重要，但不凌驾于真正解决问题之上。
