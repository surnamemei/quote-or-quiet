# S36: L1 with truth-relative errors (pre-registration, 2026-11-09, before building the review sheet)

L1: the frozen system's silent-error rate is at least 50% below the strong baseline's at the same coverage.
Strong baseline: the agreement-score rule on the same evidence and the same generations (combo_plain candidate, score = agreeing outputs among the five other 4B outputs plus Phi-4, 0..6), at the strictest threshold whose coverage is at least the system's, per test set (FRESH-5, Mintaka test, PopQA test).
Why truth-relative: S35 found that the gold-relative errors of the frozen system are almost all benchmark errors (stale or wrong gold, other readings). These hit both rules alike and dilute any difference. Silent error means an answer that is wrong, so errors are judged against the facts, blind.

Sheet: every release of either rule that is gold-wrong (system and baseline, shared answers once), plus 30 random gold-correct releases that only the baseline makes and 30 that only the system makes (to catch errors the gold misses), plus 15 injected-false decoys. Question and answer only; which rule produced a row is hidden. Two blind model reviewers per row, verdicts correct / correct for one reading / wrong / cannot tell.
A release counts as a truth-relative error if both reviewers say wrong. Errors found in the gold-correct samples are scaled up to their populations and reported, but the primary count uses the gold-wrong rows only (all of them reviewed).
Primary test, pooled over the three sets: k_sys and k_base truth-relative errors at matched coverage. L1 holds if k_sys <= 0.5 k_base and a one-sided exact binomial test on the errors that only one rule makes (discordant errors), H0: P(system-only) >= 1/3 (that is, system errors >= half of baseline errors), rejects at 5%.
Validity: at least 14 of 15 decoys called wrong by both reviewers; otherwise the review is repeated with new reviewers.
Reported regardless of outcome; the gold-relative comparison (49 vs 54 pooled) stays in the paper as the secondary result.

## Amendment (2026-11-09, before any review; after the builder printed the gold-relative counts)
The baseline at "the strictest threshold with at least the system's coverage" releases clearly more than the system (t = 5 on all three sets: 631 vs 568, 832 vs 620, 450 vs 401), which would compare the system against a baseline with more coverage and so more errors. Matching is changed to exact coverage: the baseline releases every question with score above t and a random share of the score-t questions that brings it to the system's release count, and its error count is the expected value: errors with score > t plus (system releases - releases above t) / (releases at t) x errors with score = t. The sheet is unchanged (it holds every baseline release at score >= t); the key records each baseline item's score. Truth-relative errors at the edge score are counted fractionally. The test is then a comparison of k_sys with the expected k_base: L1 holds if k_sys <= 0.5 E[k_base] and a one-sided test, computed by drawing the edge share at random 10,000 times (seed 0) and taking the share of draws where k_sys > 0.5 k_base, is below 5%, plus the discordant-error binomial test as before on the draw-averaged counts.
